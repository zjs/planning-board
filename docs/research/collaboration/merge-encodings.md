# Merge scenarios: candidate encodings

_Generated by `spikes/merge-scenarios/encodings.test.ts`. Don't edit by hand. The reading is in [`merge-scenarios.md`](merge-scenarios.md)._

Each experiment takes a problem from [`merge-results.md`](merge-results.md) and tries a different way of laying out the document, on bare Yjs, before anything in the app's schema changes. Alice has the lower client ID throughout.

| # | Fixes | Encoding | Result |
|---|---|---|---|
| E1 | L1, O1 | Time stored as one value, `time: "q2"`, rather than a set of values | Concurrent drops to Q2 and Q3 leave exactly one value, q3: the person with the higher client ID wins. There's never a second value hiding in the document. |
| E2 | U2 | The same register, with Alice undoing after Bob moved the card again | After Alice's undo the card is in q3. Yjs's undo leaves a value someone else has overwritten alone, so Alice's ⌘Z does nothing visible here. |
| E3 | L18 | Areas as flat keys on the card, `"system:billing": true`, with no nested set to create | Two people giving an untagged card its first area leave it in billing and identity, the same as when it already had one (L2). The first value is no longer special. |
| E4 | L11, O4 | A deleted card keeps its entry, marked `deleted: true` (a tombstone) | The card is deleted for both people, and Bob's concurrent rename is kept inside it. When Alice undoes, it comes back for both of them as "Account recovery by email". Removing the entry, as today, throws the rename away. |
| E5 | L9, O4 | Tombstones, read with one rule: a card shows only if neither it nor any group above it is deleted | "WebAuthn fallback", added inside the group while it was being deleted, is hidden with its group. Restoring the group brings it back inside, instead of leaving it loose on the board with no sign of where it came from. |
| E6 | L16 | A value's label, parent and order as separate keys in its own map | A rename and a reorder made at once both stick: the area is "Platform services" at order a0V. |
