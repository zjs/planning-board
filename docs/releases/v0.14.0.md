This release is about trusting a relay: what whoever runs one can and can't do, checked with formal models, and ways to keep them out of the app you use. It also gets a hosted demo relay ready to deploy.

## What's new

- **A threat model** of the relay, with whoever runs it as the attacker: what they can see, what they can't, and how each claim is established ([threat model](https://github.com/zjs/planning-board/blob/main/docs/security/threat-model.md)).
- **Formal models, run on every change:**
  - a protocol proof that a relay can't read or forge a plan;
  - models of syncing, with offline work, crashes and restores, and of grouping;
  - random schedules of the real app and relay, checked for the same properties.
- **A relay can serve no app.** With `-serve-app=false`, `/` says where to open the app instead, and the relay carries only encrypted plans.
- **The app's HTML file comes with each release,** as `planning-board.html`, with a checksum and a build attestation, so a copy can be checked before it's opened from disk or hosted at an address of your own.
- **File › Open a share link…** opens a link someone sent in whichever copy of the app you have open, such as that HTML file.
- **Opening a share link asks your name,** the first time, so others see who joined.
- **For running a public relay:**
  - `-expire-idle` deletes plans nobody has opened or changed for a while;
  - `-privacy-note` serves a page at `/privacy`;
  - `-client-address-header` reads each person's address from a header the proxy sets itself, such as Fly.io's `Fly-Client-IP`.
- **A fix to catching up:** a browser whose first visit to a shared plan was cut short, while the relay was then restored from a backup, could miss the plan's first changes. It now starts again from nothing.

## Opening older plans

Plan files, changes files and browser boards saved by earlier builds open in this one with nothing lost. CI checks that on every change.

## Before upgrading a relay

- **On HTTPS, links no longer open the relay's own copy of the app.** Links shared from a page the relay served now open the [hosted page](https://zjs.github.io/planning-board/) instead, so the people you share with need to be able to reach it, and the relay must accept pages from it. If you set `-allow-origin`, keep `zjs.github.io` in the list. Links shared from a copy of the app at your company's own address keep opening that copy.
- **Behind a proxy, `-trust-forwarded` reads the last `X-Forwarded-For` entry,** the one your proxy added, where it used to read the first, which the person's own browser could set. With one proxy, as in the [hosting examples](https://github.com/zjs/planning-board/blob/main/docs/hosting.md), nothing changes. Behind a proxy that sets its own header instead, use `-client-address-header`.
- **To keep the app off the relay,** add `-serve-app=false`. People then open the hosted page, your company's copy, or the HTML file. Over plain `http`, only the HTML file can reach the relay. If people have been opening the app from the relay, read [what to do first](https://github.com/zjs/planning-board/blob/main/docs/hosting.md#upgrading):
  - plans kept only in a browser at the relay's address stay there, so save them to files first, and let offline changes go out;
  - links that open the relay's address stop opening the app, but pasted into **File › Open a share link…** in a copy of this release, they still work;
  - copies of the app older than this release keep making links that name the relay.

Stop the relay, replace the program or pull the new image, and start it again with the same data folder. Boards that were open reconnect on their own. [`docs/hosting.md`](https://github.com/zjs/planning-board/blob/main/docs/hosting.md#upgrading) has the details.

## Checking a download

- **Checksum:** `sha256sum -c SHA256SUMS --ignore-missing` in the folder you downloaded to, or `shasum -a 256 -c SHA256SUMS --ignore-missing` on a Mac.
- **Where it was built:** `gh attestation verify planning-board.html --repo zjs/planning-board` checks that the file came from this repository's release workflow. The same works for each relay archive, and for the image: `gh attestation verify oci://ghcr.io/zjs/planning-board:0.14.0 --repo zjs/planning-board`.

`planning-board-relay -version` names the commit it was built from.
