The first numbered release of Planning Board. Until now there was only `relay-latest`, rebuilt from every change, so there was nothing to pin. From here on, each round of work ends in a version like this one.

## What's in it

Everything the [README](https://github.com/zjs/planning-board#status-early-preview) lists under "Works today":
- **On your own:** pivoting, groups, dependencies, find, and the guided start from a blank plan.
- **Together:** sharing through a relay, live editing with presence, Activity and a card's history, and sharing by file where no relay is allowed.
- **In and out:** Jira CSV import, plan files, and several plans per browser.

The app is the same single HTML file as the [hosted page](https://zjs.github.io/planning-board/), and it's inside each relay download.

## Opening older plans

Every plan file, changes file and browser board saved by any earlier build opens in this one with nothing lost. CI checks that on every change, against files saved by each earlier build.

## Upgrading a relay

Stop the relay, replace the program or pull the new image, and start it again with the same data folder. Boards that were open reconnect on their own. [`docs/hosting.md`](https://github.com/zjs/planning-board/blob/main/docs/hosting.md#upgrading) has the details.

- **Container:** `ghcr.io/zjs/planning-board:0.13.0`.
- **Downloads:** below, one archive per computer.

## Checking a download

- **Checksum:** `sha256sum -c SHA256SUMS --ignore-missing` in the folder you downloaded to, or `shasum -a 256 -c SHA256SUMS --ignore-missing` on a Mac.
- **Where it was built:** `gh attestation verify planning-board-relay-linux-amd64.tar.gz --repo zjs/planning-board` checks that the file came from this repository's release workflow. The same works for the image: `gh attestation verify oci://ghcr.io/zjs/planning-board:0.13.0 --repo zjs/planning-board`.

`planning-board-relay -version` names the commit it was built from.
