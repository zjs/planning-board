# Docs

What's here, for anyone finding their way around the repository. Some documents describe the tool as it is now; most are records of how it got here, kept public as a decision log.

## The tool as it is

- [`requirements.md`](requirements.md): what the tool is for, its requirements, and what's out of scope.
- [`decisions/`](decisions/README.md): architecture decision records, one per significant choice, with an index and their statuses.
- [`hosting.md`](hosting.md): running the relay for a team, from a laptop pilot to a server.
- [`releases/`](releases/): the notes for each numbered release.
- [`housekeeping.md`](housekeeping.md): how the repository is kept tidy, including the definition of done for every change.
- [`self-review.md`](self-review.md): the brief for the separate Claude session that reviews each pull request.

## Product questions and feedback

- [`questions.md`](questions.md): every product question engineering raised, with the options, a recommendation and the product manager's answer. Open ones are at the top.
- [`backlog.md`](backlog.md): feedback, grouped into themes, and where each landed. Repository housekeeping is at the end.

## Records

These describe a moment, and stay as they were written. A later decision supersedes them rather than editing them.

- `sprint-N.md`: what each sprint set out to do, and its exit criteria.
- [`plans/`](plans/): how engineering planned each sprint, slice by slice, and the plan for collaboration, `m2-plan.md`.
- [`demos/`](demos/): a demo note for each sprint (what to click, what should happen, known gaps), and scripts for tester sessions.
- [`research/`](research/collaboration/README.md): the research behind collaboration, including prior art, merge experiments and the relay's design.
- [`reviews/`](reviews/): reviews engineering wrote for the product manager, such as the UX assessment and the repository review.
- [`samples/`](samples/): the synthetic Jira export used by tests and the import guide. No real roadmap data is ever committed.
